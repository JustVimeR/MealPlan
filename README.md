# MealPlan

> Мінімалістичний веб‑додаток для планування харчування. Проєкт у активній розробці.

---

## ✨ Коротко

MealPlan допомагає планувати меню, (опціонально) підраховувати калорії та формувати шопінг‑лист. Репозиторій структуровано на **веб‑клієнт** та **API** (монорепо‑стиль).

> **Статус:** MVP у розробці · інтерфейс та бекенд поступово доповнюються

---

## 📦 Структура репозиторію

```
MealPlan/
├─ meal-plan-web/     # фронтенд (React + TypeScript + Tailwind CSS)
├─ meal-plan-api/     # бекенд API (у розробці)
└─ README.md
```

---

## 🧭 Можливості (поточні/заплановані)

* Планування меню (опціонально)

> Примітка: функції позначені як *опціонально* — у процесі реалізації, API/дані можуть бути заглушками.

## 🚀 Швидкий старт (локально)

### Вимоги

* **Node.js ≥ 18**
* **npm** або **yarn**/**pnpm**

### Клонування репозиторію

```bash
git clone https://github.com/JustVimeR/MealPlan.git
cd MealPlan
```

### Встановлення залежностей

> Якщо немає спільного workspace — встановіть залежності окремо для кожного пакета.

**Фронтенд**

```bash
cd meal-plan-web
npm install   # або: yarn install / pnpm install
```

**API** (якщо передбачено локальний запуск зараз)

```bash
cd meal-plan-api
npm install
```

### Запуск у режимі розробки

**Фронтенд**

```bash
cd meal-plan-web
npm run dev    # або: npm start / yarn dev
```

**API** (коли буде готово)

```bash
cd meal-plan-api
npm run dev
```

Після запуску фронтенда відкрийте: [http://localhost:3000](http://localhost:3000)

## ⚙️ Налаштування середовища

> Залежно від реалізації можуть знадобитися змінні середовища.

**Приклад (фронтенд):**

```
# meal-plan-web/.env.local
VITE_API_URL=http://localhost:4000
```

**Приклад (API):**

```
# meal-plan-api/.env
PORT=4000
DATABASE_URL=...
JWT_SECRET=...
```

> Конкретні ключі будуть уточнені після стабілізації API/схеми даних.

---

## ☁️ Розгортання (web) — Vercel (опціонально)

1. Підключіть репозиторій до Vercel
2. Оберіть каталог **`meal-plan-web`** як root для фронтенда
3. Вкажіть build‑команду (наприклад `npm run build`) і output‑директорію (наприклад `dist`)
4. Додайте потрібні змінні середовища (наприклад `VITE_API_URL`)
5. Запустіть деплой — після успіху отримаєте продакшн‑URL

> Для API оберіть відповідну платформу (Railway/Fly.io/Render/Serverless) — за потреби додайте окремий розділ з інструкцією.

## 🧪 Скрипти (приклади)

> Назви можуть відрізнятися — звіряйте з `package.json` всередині відповідних папок.
